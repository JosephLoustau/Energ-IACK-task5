1. Overview

The Rapport HTML button in the app's top bar builds a single, self-contained HTML file and opens it in a new tab. The file holds its own data, styles and script, so it works fully offline. It is laid out like an A4 document and prints to PDF cleanly.

The report covers the strategy selected in the app and the buildings that pass the app's filters (usage, search). Inside the report the reader can still change three levers (thermostat, annual budget, social cost of carbon), rewrite the text, and download the result.

2. Files

App.tsxexportReport() collects the filtered buildings and the strategies (both presets, plus the custom one when it is selected) and calls new HtmlReport(…).open().

The building model itself (thresholds, condition curve, generic renovation) is in model.ts and shared with the app; the map symbols come from symbols.ts.

All heavy work happens once, in the app. With 2 strategies, 3 thermostat levels and 6 budgets, that is 36 scheduled plans (54 with a custom strategy). The report only looks them up when the reader switches a lever, so switching is instant. The one value computed live is the social cost of carbon, because it is a free number: it only multiplies tonnes already in the payload.

The payload stores the buildings once, then for each strategy and thermostat level: the due year and triggered criteria of each building, and for each budget the scheduled works ([building index, works year, cost, tCO₂e/yr saved, residual flag]) and the yearly series. The file weighs about 880 KB for the full stock.

4. How the numbers are computed

1 · ThermostatA reduction of n °C multiplies every building's IDC and CO₂ by (1 − 6 % × n) from 2026, before anything else. Fewer buildings then cross a threshold.
2 · AssessmentUnchanged from the app (assessPortfolio): first year between 2026 and 2036 when one criterion (IDC, condition, CO₂) crosses its threshold, then priority order.
3 · SchedulingBuildings in priority order, each in the first year ≥ max(due year, 2028) where the annual budget still has room. Its cost is computed at that year, so a delayed building costs more. A building above the cap takes a year alone.
4 · SeriesYearly investment and count; emissions = stock emissions minus the savings of works completed the year before. Cumulative emissions sum 2026–2050.
5 · Carbon costFull cost = investment + CSC × cumulative emissions 2026–2050, undiscounted. Per building, "net CSC" = cost − CSC × tonnes saved until 2050.
6 · LeversChange one input at a time against the chosen scenario, then search all combinations for the lowest full cost and the lowest emissions.

Planning hypotheses

They sit in PLANNING in plan.ts:

firstWorksYear: 2028        // one year of studies + one year of tender after 2026
horizonYear:    2050        // end of the trajectory (climate-neutrality target)
budgetLevels:   [40, 60, 80, 120, 200 MCHF/yr, no cap]
defaultBudget:  80 MCHF/yr
comfortLevels:  [0, 1, 2]   // °C of thermostat reduction
savingPerDegree: 0.06       // heat demand saved per °C
defaultScc:     177         // CHF/tCO₂e

These are team hypotheses, not validated values. The 6 %/°C rule of thumb and the 2028 start in particular should be checked with the City before the report is shared outside the team.

6. What the reader can do

  • Thermostat (0, −1, −2 °C), Budget (40 to 200 MCHF/yr or no cap) and CSC (free number, default 177 CHF/t) in the toolbar. The "?" next to Thermostat and CSC explains each lever.
  • ✎ Modifier le texte: titles, key sentences, summary and takeaway panels become editable. Edits survive lever changes, are marked by a yellow bar in the margin, and can be reset with Rétablir.
  • Télécharger: saves the report as an HTML file, including the text edits (stored in a report-texts JSON block and reloaded on opening).
  • Export CSV (Annexe A): the building list for the current scenario, with the parameters in the first row.
  • Print → PDF: the toolbar and buttons are hidden, each page breaks on A4.

An edited sentence is frozen: if the reader edits the summary and then changes the budget, the figures in that sentence no longer match. Edit last, or reset.

7. How to change things

The wording

Edit texts.ts. Each key is one sentence or label; the comment above it lists its placeholders, e.g.

// {count} {firstYear} {end} {budget}
s2Claim: '{count} bâtiments rénovés de {firstYear} à {end}, par lots annuels de {budget} au plus.',
  • Placeholders receive values that are already formatted (numbers with Swiss separators, MCHF, years). An unknown placeholder renders as empty.
  • Light HTML is allowed (<b>, <br>, <p>).
  • Keys ending in a clause (summaryThermostat, summaryResidual, s3BestCo2…) are optional fragments added only when they apply; they start with a space.
  • Annexe B's method is the hypotheses list.
  • HtmlReport also accepts texts in its options to override keys per export, e.g. for another language or another city.

Chart, table and legend labels are not in texts.ts; they are in runtime.js.

A new sentence or block

  1. Add the key to texts.ts.
  2. Use it in runtime.js with T('myKey', { value: … }).
  3. To make it editable by the reader, wrap it: ed('my-id', T('myKey')), or use band('my-id', text, note) for a takeaway panel. Ids must be unique and stable, since saved edits are keyed on them.

The page helpers in runtime.js are page() (an A4 sheet with footer and number), head() (eyebrow, title, key sentence, side note), figure() (chart + legend + "Figure n —" caption + source) and band() (takeaway panel).

The hypotheses, levels and defaults

Change PLANNING in plan.ts. Adding a budget or thermostat level adds plans to the payload, so the file grows roughly in proportion. The renovation costs and thresholds are in model.ts (RENOVATION, PRESETS) and also change the app.

The look

The report follows the app's graphical chart (src/styles.css): Helvetica Neue, warm greys, Geneva yellow, and one colour per scenario (--scenario-color, set from data-strategy on body). That colour marks the KPI card borders, the takeaway panels, the active controls and the works-year ramp. The chart series --s1..--s3 are the app's scenario colours, with --s1 lightened (#e8646f) so red and green stay apart for colour-blind readers. If the app's colours change, update the variables at the top of report.css. Page size and margins are on .page.

8. Constraints and pitfalls

  • No </script> in runtime.js. The runtime is inlined in a script tag; that literal would end it early. Write <\/script> in strings.
  • runtime.js is not type-checked. It is plain JavaScript inside a string. Keep computation in plan.ts (typed and tested) and keep the runtime to lookups and drawing. Run node --check src/report/runtime.js after editing it.
  • The payload escapes < so building names can never break out of the data block. Keep it that way if you add fields.
  • Size grows with combinations. Strategies × thermostat levels × budgets plans are precomputed. Add levels with care.
  • Line endings. Repository files are CRLF; keep new files in CRLF.
  • The report opens from a blob URL. Browsers allow it because it follows a click; some popup blockers may still ask for permission.

9. Tests

npm test               # vitest: model + report
npx tsc --noEmit       # types
node --check src/report/runtime.js
  • The scheduler starts no earlier than 2028, skips buildings with no threshold crossed, respects the budget, and prices delayed works at their year.
  • CO₂ gains start the year after works and are never counted twice; yearly investment adds up to the total.
  • A tighter budget never ends earlier nor emits less; a lower thermostat never adds works and lowers emissions.
  • The HTML is self-contained and building names cannot close the script tag.
  • Every text key used in the runtime exists in texts.ts.

10. Known limits

  • The renovation is one generic intervention; heat-pump or district-heating feasibility, heritage protection, subsidies and inflation are not modelled.
  • The full cost leaves out energy savings and emissions after 2050, which favours the cautious strategy. At 177 CHF/t the ambitious strategy only pays off for society above roughly 10 000 CHF/t.
  • Lowering the thermostat can reduce ambition: buildings that fall under the thresholds leave the programme and keep fossil heating, so 2050 emissions can end higher. The report flags it when it happens.
  • The scheduler is a greedy rule, not an optimisation; it keeps the app's priority order.
  • The maps have no background tiles, so the file stays self-contained; 1 % of outlying buildings on each side are left out of the frame and counted in the caption.
